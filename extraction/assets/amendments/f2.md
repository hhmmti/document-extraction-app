# F2 clarification and revision for the newer report generator (draft, awaiting approval)

Clarifies `f2-championx.md` §1, which `f2-pass-a.md` Step 0 repeats, and revises the contract's §2, §3 and §8 and pass-A Steps 1 to 3 for a newer version of the report generator. Where the pass-A prompt or the contract disagrees with this block, this block wins.

> §1: "Page 1 must show **all** of: … a **`ChampionX Representative`** block"
>
> Step 0: "Page 1 must show ALL of: … a `ChampionX Representative` block"
>
> §2: "**9 pages, fixed. This family does not vary its page count** (n=5)." … "No optional page groups. A missing page is a **HALT**, not an absence."
>
> Step 1: "This family has NINE PAGES, FIXED, at n=5." … "A missing page is a HALT, not an absence — report it and stop."
>
> Step 2: "`section_role`: `gas_handler` for the Gas Handler body; `primary` for the MAIN PUMP body."

**Clarification (§1, Step 0): the representative block.** A newer version of the report generator may print the representative block under the label `Account Manager | Customer Rep`, and may show the vendor name only in a logo image, so that the name is nowhere in the page text. A block printed that way is the representative block §1 and Step 0 require. The title and the five section headings are still required on page 1, as written.

**Revision (§2, Step 1): the page count.** The page count is not fixed. The newer generator prints 7 pages: it leaves out p8–9, the `ESP Setting Depth Survey` page and the remaining plots. Read p8–9 when they are printed; when they are not, record that in Extraction Notes, and do not HALT. Blocks also move between pages, because a longer block pushes the next one onto the following page. Read each block by its title on whichever page it prints, and cite that page in `source_page`; the page numbers in §2, §3, §8 and Steps 1 to 3 say where a block usually prints. Every other block the contract reads is still required: one printed on no page is a HALT under V-02, named by its title. The one exception is the gas handler block, which prints only when the string has a gas handler. "All nine pages read" in the Definition of done means every printed page.

**Revision (§3, §8 F2-09 and F2-30 to F2-34, Steps 2 and 3): a charge pump in place of a gas handler.** The string may have a charge pump instead of a gas handler: a pump body of a second model, below the main pump. It prints as a `CHARGE PUMP` equipment string on p1, and as a `Charge Pump <n>` block with the gas handler block's field set. It is a pump body and is in scope. Read F2-09 and F2-30 to F2-34 from it as from a gas handler, and apply Steps 2a and 3 to it unchanged, with `BHP Charge Pump <n> Only` in place of `BHP Gas Handler Only`. Its `section_role` is `taper`, the schema's role for a pump body of a second model in the string, never `gas_handler`. Like every body, its `section_order` comes from the p2 `Set Depth` column. When the string has neither a gas handler nor a charge pump, F2-30 to F2-34 go under *Fields not found*.

**Clarification (§3, Step 3b): the `GAS HANDLING` label.** The gas separator's equipment string may begin `GAS HANDLING`, on p1, on p2 and in the `Gas Separator / BOI` block. That string names the separator, not a gas handler: it is section context only, and the block's hydraulics go to `stg_gas_cascade` as Step 3b says.

**Example (§2, §3).** A 7-page document whose p5 prints the `Gas Separator / BOI` and `Charge Pump 1` blocks, and whose p6 prints the `Main Pump` and `Motor` blocks, is complete. Its `stg_pump_config` has one row per model: the charge pump as `taper` and the main pump as `primary`, ordered by the p2 set depths.
